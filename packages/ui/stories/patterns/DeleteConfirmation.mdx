# Delete confirmation

Deleting asks once, names what goes, and says what the server answered. Instance: deleting a slot on `/mentor/slots` (`DeleteSlotDialog`, built on `AlertDialog`).

<Canvas of={Stories.Open} />

## Rules

| Rule | Source |
|---|---|
| Use `AlertDialog`, not `Dialog`: the question needs an answer. | WAI-ARIA alertdialog |
| The title names the object and the detail that tells it apart ("Delete the slot on Thu 22 Oct, 18:00?"). | prompt (stage 3) |
| One sentence of consequence, including what can be undone ("You can add it again later."). | R01.5 |
| Buttons are verbs with the object: *Keep slot* and *Delete slot*; the destructive one is `destructive`, never the accent. | B51, T10 |
| Focus starts on the safe choice. | B51 |
| While the request runs the buttons are disabled and the dialog cannot be dismissed. | one submit at a time |
| A refusal (`conflict`) stays in the dialog, in the server's words, so the person sees why and can back out. | C58 |
| After success the page moves focus to a stable place (the list heading) – the row that had it is gone. | WCAG 2.4.3 |
| The trigger's accessible name includes the object, because rows repeat. | `AGENTS.md` |
