# Payment and waiting

Paying happens on a hosted page, and confirmation arrives later by webhook (spec E02: card only, D16). The pattern covers the minutes in between so the mentee always knows what is going on and nothing happens twice.

<Canvas of={FormStories.RedirectingToCheckout} />

## Rules

| Rule | Source |
|---|---|
| The price is on the button (*Pay PLN 180.00*) and in the summary before the question. | R01.4 |
| What happens next is said before paying: the time is held for 35 minutes; the mentor may decline; a decline or a missed deadline is a full refund. | spec E02, UI/UX |
| After the server creates the booking the button stays busy ("Opening payment…") until the browser leaves – no second booking by double click. | C65 |
| A refused booking is explained in words: the time was just taken; finish the previous payment first; payment is unavailable and nothing was charged. | spec E02 (Edge Cases) |
| Back from the payment page the status is *Payment processing…* until the webhook lands; the page re-checks every few seconds for up to a minute. | spec E02, UI/UX |
| After a minute the spinner stops and the page says "This page will update shortly" and keeps checking more slowly, so the sentence stays true. | C66, C67, WCAG 2.2.2 |
| The success redirect never marks a payment as paid; only the status from the server does. | spec E02 (Stripe guidance) |
| A payment that arrives after the time was released is refunded and says so. | spec E02 (late paid webhook) |
