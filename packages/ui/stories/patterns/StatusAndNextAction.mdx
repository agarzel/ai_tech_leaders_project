# Status and next action

At the top of a detail page the person reads where things stand and what, if anything, they do next. Instance: the booking state machine in `BookingStatusPanel`, for the mentee and the mentor.

<Canvas of={Stories.DeclinedMentee} />

## Rules

| Rule | Source |
|---|---|
| The title is the state in words, with the time that matters ("they decide by Tue 27 Oct, 05:00 (Europe/Warsaw, UTC+1)"). | R01.5, spec E02 |
| One sentence says what happens next; refund sentences say banks take a few days. | spec E02, UI/UX |
| The next action, when there is one, is the screen's one accent: *Find another mentor*, *Choose a time again*. Waiting states have no action. | P5/K3 |
| Refund wording follows the payment status: "on its way" while requested, "Refunded" only when done, "Refund delayed — we are on it" when it failed. | spec E02 (Refund lifecycle) |
| The mentee sees the mentor's reason; the mentor never sees refund details. | spec E02 |
| Rows use `BookingStatusBadge`, a phrase; pages use the panel, a sentence. | C68 |
