## Input for the E03 specification (agent test)

A new session built the *Cancel booking* screen (#34, R04) from this documentation only. The design-system gaps became rules ([Contributing](?path=/docs/design-system-contributing--docs), [How to choose](?path=/docs/design-system-how-to-choose--docs), the patterns). The product gaps below cannot be settled by the design system; the E03 spec (#33–#36) must decide them. The test screen was not kept in the repository. Source: agent test 2026-10-20 (lekcja-06/test-agentem.md).

| Gap | Question for the spec | What the agent guessed |
|---|---|---|
| 3 | Is there a `cancelled` booking status? Its wording for the mentee and for the mentor, its badge, and whether the mentor sees "paid" | "Cancelled – refund on its way" / "Cancelled – no refund" |
| 4 | The API contract of cancelling: route, answer, refusal | `POST /api/bookings/:id/cancel` returning `{ refund: "full" \| "none" }`, refusal 409 |
| 5 | The 12 h threshold passes while the dialog is open: does the dialog recompute? | no recomputation; the server decides |
| 6 | What the page does after the server refuses (*the session has already started*): message only, or refresh the booking | message in the dialog, no refresh |
| 7 | The definition of "session finished" | `startsAt + lengthMinutes` |
| 14 | Who supplies the free-cancellation threshold: the client computes it for a preview only | proposal: `freeCancellationUntil` in `BookingDto`, like `acceptBy` |
| 16 | Status of #34 stated differently in two files | fixed: "Not built – no E03 spec" everywhere |
| 17 | The component table has no row for the cancel component | nothing to do now; add the row when the component is built in E03 |

Two design-system items stay open because they need code, not words:

| Item | State | Priority |
|---|---|---|
| A generic deadline component with the verb as a prop (`AcceptDeadline` fixes "Decide"; the pattern is documented) | planned for E03, not built (gap 13) | Medium |

## Known limits of this documentation

- Interaction tests run in Chromium; native date and time pickers are exercised by setting a value, not by clicking the picker.
- Screens are compositions in Storybook; real pages, routing, server data and `from=` entry points are app work.
- The agent test was run on 2026-10-20 (screen *Cancel booking*, 57 decisions: 28 rules, 11 examples, 18 guesses). Every guess became a rule or an entry on this page (lekcja-06/test-agentem.md).
