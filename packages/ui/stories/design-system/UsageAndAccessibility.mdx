# Usage and accessibility

Rules that hold on every screen. Each has its source; **proposal** means no source yet and the owner has not decided. Automatic checks: every story runs axe in both themes and fails on a violation (`npm run test:storybook`). Axe cannot judge reading order, wording or whether a screen reader says something sensible – those are checked by hand, and stage 5 of the work log lists what was and was not checked.

## Keyboard and focus

| Rule | Source |
|---|---|
| Everything a mouse can do works with the keyboard; the tab order follows the visual order and the DOM order. | WCAG 2.1.1, 2.4.3 |
| Focus is always visible: a neutral ring (`ring-3 ring-ring/50`) on buttons, fields, links, rows and nav links – one style, not the accent. | T4, WCAG 2.4.7, 1.4.11 |
| A control is at least 24 × 24 px; fields and buttons are 32 px, 40 px on touch (`pointer: coarse`). | P4, WCAG 2.5.8 |
| A dialog traps focus, closes with Escape and returns focus to the control that opened it. | WAI-ARIA dialog pattern |
| In a confirmation the safe choice (*Keep slot*) comes first and has focus when it opens. | B51; prompt stage 3 |
| Menus open with Enter or Space and move with the arrow keys; tabs move with the arrows and are activated with Enter or Space. | WAI-ARIA menu and tabs patterns, B59 |
| In the session composer Enter sends and Shift+Enter adds a line (only in the session view, not built yet). | R02.2, K4 |
| An icon-only control has an accessible name and a tooltip with the same text. | WCAG 4.1.2, 2.5.3 |
| After deleting or declining, focus moves to a stable place (the list heading), not to `body`. | C58, C69, WCAG 2.4.3 |

## Forms and messages

| Rule | Source |
|---|---|
| Every field has a visible label above it; a placeholder is only an example. | WCAG 3.3.2; prompt stage 3 |
| Hints and errors are linked to the control with `aria-describedby`; the error comes with an icon and says what to do. | WCAG 1.3.1, 3.3.1, 3.3.3, B10 |
| Optional fields say "(optional)"; required fields carry no marker. | answer 2.5, B11 |
| A changed field is checked when the person leaves it; after a failed submit focus goes to the first error. | C20; prompt stage 3 |
| Typed values stay after an error; the submit button is disabled and says *Saving…* while it waits. | prompt stage 3, B18 |
| Success is shown only after the server confirms. | prompt stage 3 |
| A disabled control always has its reason as visible text next to it, never only in a tooltip. | B17; prompt stage 4 |
| A message that is on the page from the start uses `role="status"`; one that appears after an action uses `role="alert"`. | B42, WAI-ARIA live regions |
| An error that needs action is never a toast (there is no toast). | S10; prompt stage 4 |
| A live region speaks once: the shadcn `Spinner` already has `role="status"`, so do not wrap it in another. | `packages/ui/AGENTS.md` |

## Colour

| Rule | Source |
|---|---|
| Text 4.5 : 1, interface elements 3 : 1, measured in both themes on the [Color](?path=/docs/foundations-color--docs) page. | WCAG 1.4.3, 1.4.11 |
| Colour is never the only carrier of meaning: a status has a word, an error has text and an icon. | WCAG 1.4.1 |
| The accent (`primary`) marks one element per screen. Statuses use `secondary` or `outline` badges. | R01.5/P5, K3, T10 |
| Links in text are `foreground` with an underline. | T11 |
| Row separators may stay below 3 : 1 because they are decoration; field outlines, focus rings and error outlines meet 3 : 1. | T5 |
| Use semantic classes; both themes come from the same class. `dark:` variants appear only inside primitives. | prompt rule 3; Themes page |

## Motion and content

| Rule | Source |
|---|---|
| Motion confirms an action and never decorates: no sounds, no entry animation for messages, fades of about 100–150 ms for overlays. | R02.2/P8, R02.4/P10; durations are **proposal** F3 |
| With `prefers-reduced-motion: reduce` animations and transitions are removed; state changes stay visible. | WCAG 2.3.3; F3 (**proposal**) |
| Running text is at most about 65 characters wide (`max-w-prose`). | WCAG 1.4.8, F2 |
| No emoji in interface text; a person may type one in a message. | R02.5/P11 |
| Icons next to a visible label are hidden from screen readers (`aria-hidden`); a stand-alone icon never carries meaning alone. | WCAG 1.1.1, 1.4.1; Icons page |
| Long names and links wrap (`break-words`) or are cut with the full text in `title`; nothing overflows at 320 px. | WCAG 1.4.10 |

## Layout and widths

| Rule | Source |
|---|---|
| Check every screen at 320, 768 and 1440 px; at 320 px one column with no horizontal scroll of the page. | WCAG 1.4.10; prompt stage 1 |
| Content stays in a column of at most `max-w-5xl` (1024 px); forms use the `narrow` width (384 px). | F2 |
| Lists and panels are dense (`py-list-row`); the session view puts the conversation in the centre. | R01.1, K1 |
| One `h1` per page (`PageLayout`), landmarks are named (`nav` with a label). | WCAG 1.3.1, 2.4.1; C31 |
| A wide table scrolls inside its own frame, not the page. | WCAG 1.4.10 |

## Product rules the interface keeps

| Rule | Where you see it | Source |
|---|---|---|
| The price is visible before the person writes the question. | `/book/[slotId]` | R01.5/P5; D12 |
| A slot is bookable from 24 hours ahead; the server decides, the UI says "Not bookable – starts too soon". | `SlotList` | D13 |
| The mentor decides until 12 hours before the session; no decision means a full refund. | `AcceptDeadline`, `BookingStatusPanel` | R05, D07 |
| Every time shows its time zone. | all times | spec E01 Edge Cases |
| Only the booked question is shown, as plain text; it cannot be empty. | `BookingQuestion`, `QuestionField` | Q5, Q11 |
| Prices are PLN and are never computed in the interface. | `PriceList`, `BookingSummary` | D12; spec E02 |
| No ratings, reviews, "years of experience", counters or hype numbers; public work links instead. | `MentorCard`, `PublicWorkLinks` | N02, A03, A05 |
| Mentors learn about bookings in the app only: one sentence with the number, no counter badge. | `PendingBookingsNotice` | D15, P10, Q2 |
| The mentor never sees refund details, only that the mentee is refunded. | `MentorBookingRow` | C68, Q14 |
| A link is shown once and copied by the person; an old link cannot be shown again. | `InvitationLinkPanel` | spec E01 |
| Card payment only; the payment page is hosted. | `BookingForm` | D16 |
| The accent on `/mentor/bookings` goes to *Accept* of the nearest deadline; none on `/m/[slug]`. | `MentorBookingRow` | Q3 |
