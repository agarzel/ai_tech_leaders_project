# Skeleton

`import { Skeleton } from "@devmentor/ui/components/ui/skeleton"`

## 1. Purpose

Shows the shape content will take before it arrives, so a list or panel does not jump once the real data loads.

## 2. When to use

| Situation in DevMentor | Source |
|---|---|
| A list of rows (bookings, slots) while its first page is loading | prompt stage 4 (loading: skeleton for content that keeps its shape) |
| A panel whose data has not arrived yet (mentor checklist panel) | prompt stage 4, Motion proposal P5 |

## 3. When not to use

| Instead of a skeleton… | Use | Why |
|---|---|---|
| A short wait inside a button (submitting a form) | `Spinner` inside the button | prompt stage 4 ("the spinner only inside a button or a short status") |
| A page-level wait with no shape yet known | `LoadingMessage` (`Spinner` + text) | nothing to outline yet |
| An empty result (zero rows, confirmed) | `EmptyState` | loading and empty are different states |
| A failed request | `ErrorMessage` | – |

## 4. Anatomy

One part: a `div` with `bg-muted`, `rounded-md` (B3) and a pulse animation. Its width and height come from `className` and must match the content it stands in for.

## 5. Variants

None (rule 6). Shape comes entirely from `className`.

## 6. States

<Canvas of={SkeletonStories.States} />

One state: pulsing. It is never hovered, focused, disabled or in an error state – once data or an error arrives, the skeleton is replaced, not styled differently.

With `prefers-reduced-motion: reduce` the pulse stops and the shape stays static (B60, follows F3, WCAG 2.3.3).

## 7. Behaviour and accessibility

| Rule | Source |
|---|---|
| `aria-hidden="true"`: a skeleton carries no information a screen reader should read; the loading state is announced once by the surrounding `LoadingMessage` or list wrapper (`aria-busy`), not by every placeholder. | WCAG 4.1.2, 1.3.1 |
| Match the real content's box size, so nothing reflows when it is replaced. | WCAG 2.3.3 (no large unexpected motion) |

## 8. Content

No text, no icons. A skeleton never shows a label like "Loading…" – that belongs to `LoadingMessage` or the surrounding region.

## 9. Responsive

| Width | Behaviour |
|---|---|
| 320 px | Widths in `%` or `w-full` so the placeholder shrinks with its container. |
| 768 px and 1440 px | Matches the real row or panel width at that size. |

<Canvas of={SkeletonStories.Narrow} />

## 10. API

All `<div>` props. `className` sets width, height and radius (`rounded-full` for an avatar placeholder).

## 13. Related

- **Confused with:** `Spinner` (short, in-button wait), `LoadingMessage` (page-level wait with text).
- **Used in:** list and panel loading states (pattern *List with filters*, stage 3).

### Interaction test

A skeleton has no behaviour; there is nothing to test beyond its hidden, static markup, already covered by the accessibility check on every story.
