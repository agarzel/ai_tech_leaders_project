# Badge

`import { Badge } from "@devmentor/ui/components/ui/badge"`

## 1. Purpose

Labels the state or kind of a thing in a word or two – *Confirmed*, *Declined*, *React* – so a person can scan a list without opening each row.

## 2. When to use

| Situation in DevMentor | Variant | Source |
|---|---|---|
| Booking status in a row: *Awaiting payment*, *Awaiting mentor*, *Confirmed*, *Declined*, *Expired*, *Payment expired* | `secondary` / `outline`; `destructive` for *Declined* and failures | booking spec, T10 |
| Stack tags on a mentor (*TypeScript*, *React*) | `secondary` | mentor-accounts spec |
| A missing checklist step (*Missing*) | `outline` | mentor-accounts spec |
| The one emphasised status of a screen, next to its action | `default` (accent), at most once per screen | P5, K3 |

Status wording follows the booking states; final labels are decided on the Content page (**proposal**).

## 3. When not to use

| Instead of a badge… | Use | Why |
|---|---|---|
| An action | `Button` | a badge is not a control |
| A count of unread things, a "+12", "Top rated", "New" | nothing | P10 (no counters), A03 (no ratings), A05 (no hype) |
| A long explanation | `Alert` or text | badges are one or two words |
| Several statuses in one row | one status per row | R01.1 (no row full of labels) |

## 4. Anatomy

| Part | Optional | Notes |
|---|---|---|
| Container | no | 20 px high, `rounded-md` (B3 – not a pill, A01), `type-meta` medium |
| Text | no | 1–3 words |
| Icon | yes | 12 px, `data-icon="inline-start"`, `aria-hidden`; only to repeat meaning (*Refund failed*) |

## 5. Variants

<Canvas of={BadgeStories.Variants} />

| Variant | Choose it when | Source |
|---|---|---|
| `secondary` (default) | neutral statuses and tags | T10, B46 |
| `outline` | waiting or finished states that need no attention | T10 |
| `destructive` | a failure or a refusal (*Declined*, *Refund failed*) | T6 |
| `default` | the screen's one emphasised status – never in a list | P5, T10 |

`ghost` and `link` were removed (B39); the default variant is `secondary`, not the accent (B46).

## 6. States

<Canvas of={BadgeStories.States} />

A badge is static. Rendered as a link (`render={<a href … />}`, e.g. a tag that filters the list) it gets hover (tint) and focus (neutral ring, T4). Disabled, loading, pressed, selected and error do not apply.

## 7. Behaviour and accessibility

| Rule | Source |
|---|---|
| The status is written in words; colour only repeats it. | WCAG 1.4.1 |
| `destructive` text on its tint: 6.94 : 1 light, 7.12 : 1 dark. | tokeny.md, WCAG 1.4.3 |
| A badge is read inline with the row; do not give it `role="status"` unless it changes live. | WAI-ARIA |
| As a link it needs a name that says the action (*Filter by React*) when the text alone is unclear. | WCAG 2.4.4 |

## 8. Content

- 1–3 words, sentence case, no full stop; past participle or state (*Confirmed*, *Awaiting mentor*).
- No numbers of people, ratings or "years of experience". (A03, A05)
- No emoji. (R02.5/P11)

## 9. Responsive

| Width | Behaviour |
|---|---|
| 320 px | Badges never wrap inside; a group of tags wraps as a group. |
| 768 px and 1440 px | Status at the end of the row, before the row actions. |

## 10. API

| Prop | Type | Default | Description |
|---|---|---|---|
| `variant` | `"secondary" \| "outline" \| "destructive" \| "default"` | `"secondary"` | See Variants. |
| `render` | element | `<span>` | e.g. `<a href="…" />` for a filtering tag. |
| `className` | `string` | – | Layout only. |

## 12. Do and don't

<Unstyled>
  <DoDont
    doExample={<Badge>Confirmed</Badge>}
    doText="A neutral status in words; the accent stays on the screen's main action (T10, P5)."
    dontExample={<Badge variant="default">Confirmed</Badge>}
    dontText="An accented status in every row turns the accent into noise (R01.5)."

## 13. Related

- **Confused with:** `Button` (action), `Kbd` (keys), `Alert` (messages).
- **Used in:** admin (database state, roles), bookings lists, mentor tags; product `BookingStatus`, `InvitationStatusBadge`, `TagList` (stage 3).
