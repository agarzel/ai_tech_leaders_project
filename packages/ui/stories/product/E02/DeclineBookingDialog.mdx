# DeclineBookingDialog

`import { DeclineBookingDialog, REASON_MAX } from "@devmentor/ui/components/bookings/DeclineBookingDialog"`

Product component, concept `bookings` (E02, #32), built on [Dialog](?path=/docs/primitives-dialog--docs) because it holds a field. Related to the pattern [Delete confirmation](?path=/docs/patterns-delete-confirmation--docs).

## 1. Purpose

Confirms a decline, states the refund and lets the mentor give an optional reason.

## 2. When to use

| Situation in DevMentor | Source |
|---|---|
| *Decline* on a booking in `/mentor/bookings` | spec E02, UI/UX |

## 3. When not to use

| Instead of `DeclineBookingDialog`… | Use | Why |
|---|---|---|
| A destructive confirmation without input | `DeleteSlotDialog` / `AlertDialog` | no field to fill |

## 4. Anatomy

Trigger *Decline*, title naming the mentee, "The mentee gets a full refund and the slot is released.", *Reason for the mentee* (optional, ≤ 280, counter), an error alert, *Keep booking* and *Decline booking*.

## 5. Variants

None.

## 7. Behaviour and accessibility

| Rule | Source |
|---|---|
| The reason is optional and says so; the mentee sees it. | WCAG 3.3.2 |
| Over 280 characters the button is disabled and the field says by how much. | WCAG 3.3.1 |
| While the request runs nothing can be changed or dismissed. | C69 |
| A refusal stays in the dialog in words; the mentor can still back out. | spec E02 (Edge Cases) |
| The trigger's name carries the mentee and the time. | `AGENTS.md` |

## 8. Content

Title: "Decline the booking from \{name\}?" Buttons: *Keep booking*, *Decline booking* (destructive). The refund sentence is always there.
