# MentorCard

`import { MentorCard, MentorCardSkeleton } from "@devmentor/ui/components/mentors/MentorCard"`

Product component, concept `mentors` (E01, #28). The name comes from the spec; the look is a dense list row, not a card (C6).

## 1. Purpose

Shows one mentor in the public list with what a visitor needs to choose: who, what about, proof of work, prices, the next time.

## 2. When to use

| Situation in DevMentor | Source |
|---|---|
| Each row of `/mentors` | spec E01, UI/UX |

## 3. When not to use

| Instead of `MentorCard`… | Use | Why |
|---|---|---|
| The full profile | `MentorProfileHeader` on `/m/[slug]` | the card is a summary |
| A grid of cards, an avatar wall, ratings | never | A01, A05, N02 |

## 4. Anatomy

One list item: name as the row link (stretched over the row), one line for the headline, stack tags, public-work links side by side, the next time with its zone; both prices on the right.

## 5. Variants

None; the row follows the data.

## 7. Behaviour and accessibility

| Rule | Source |
|---|---|
| The name is the only link that covers the row; tags and work links stay above it and remain clickable. | `Item`, B36 |
| Tag and link lists are named after the mentor (*Stack of Marek Zieliński*), because they repeat. | `AGENTS.md` (unique names) |
| The headline is one line, cut with an ellipsis; the full text is in `title`. | T12 |
| Prices in tabular figures; a missing price reads "Not set". | D12, C4 |
| No accent: the whole row is one choice among equals. | P5/K3 |

## 8. Content

Name and headline as the mentor wrote them. "Next time: Wed 4 Nov, 18:00 (Europe/Warsaw, UTC+1)". No "years of experience", no counts of sessions, no stars (A03, A05).
