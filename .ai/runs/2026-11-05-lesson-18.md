# 2026-11-04/05 – Lesson 18: the tester's role, QA in parallel with AI

Target: PR #133 (#106, a mentor also gets "My bookings" in the header). Skill: `om-qa-buddy`, run in this session with Claude in Chrome as the browser. The Cezar task for this PR had run `om-auto-review-pr` instead and had no browser access.

## Flow

1. Brief in plain language and a test plan of 8 cases (2 × P0, 4 × P1, 2 × P2) before any click. Artifacts are in `.ai/qa/artifacts_20261104-143107-pr133/`, which is gitignored.
2. The runbook (`runbook.html`) was published before the AI clicked anything. Later the same file was overwritten with AI verdicts: same `KEY_PREFIX` and `data-tc` ids, so the tester's own verdicts survive the update.
3. AI execution through the UI only. Each role used a fresh test account: a mentee via `/register`, an admin created by the owner with `auth:set-password --admin` (the CLI reads `.env`, which is blocked for the agent), and a mentor invited through the admin panel. Result: 7 of 8 pass. 007 (375 px) was not run, because the window could not be narrowed and the app refuses to load in a frame (security headers from #113).
4. A blocker in the environment, not the product: the test server reloaded about 14 times a second. Its log was inside the repo, which Turbopack watches, so each logged request triggered a rebuild and a full reload. Fixed in #134 and verified after a restart.
5. Human pass by the owner (Chrome DevTools, iPhone SE 375 × 667, seeded mentor): 001, 002 and 007 pass. The owner also saw two things the AI did not (below).
6. The QA comment on PR #133 went through the owner, who posted it before merging. Knowledge base: `.ai/qa/knowledge-base/module-history.md` and `risk-hotspots.md`.

## AI vs human

| | AI | Human |
|---|---|---|
| Breadth | All 8 cases, every role on fresh accounts, keyboard order and focus ring measured, Back after logout explored | 3 cases (001, 002, 007) |
| Narrow layout (007) | Not possible from automation | Pass against the written criterion, and saw that "My bookings" wraps onto two lines |
| Missing behaviour | Not seen: it checked only what the cases asked | Saw that the header never marks the current page (`aria-current`) |
| Environment | Found and fixed the reload-loop root cause | – |

Both human findings are P2 polish and are filed as one follow-up. The AI's written cases all passed because they asked only whether things were visible, not cut off and overlapping. The human judged how the bar looks and what is absent. That is the lesson's "test oracle" point.
