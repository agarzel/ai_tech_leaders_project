## Compared with single-agent work (issues 136, 137)
- 136 and 137 were small fixes done by one agent in one pass (one PR each, no spec council); for that size the harness would have cost more than it found.
- Issue 119 touched four packages, a migration and a new route. The spec council caught a real concurrency bug (invitation revoke race) and a missing rollback plan before any code existed – work a single agent had skipped in its first draft.
- Rule I take from it: multi-model review for high-risk changes (migrations, auth, money, access control); single agent for small bug fixes.
