## Homework: a deterministic check for a bug that passed review

Bug: T-13 from lesson 16 – `CrudForm` rendered `<form>` without `method`, so a submit before hydration sent the login and registration fields (password included) as a GET query string. Spec, unit tests, two model reviews and the threat model passed it; only the ZAP baseline found it. Five other forms (booking question, mentor profile, slot, session note, session messages) had no `method` either; their inputs have no `name`, so a GET submit would send no values – for them `method="post"` is defence in depth, not a leak fix (pointed out by the first independent reviewer).

Check: ESLint `no-restricted-syntax` on `packages/{app,ui}/src/**/*.{tsx,jsx}` – every `<form>` without an `action` must have `method="post"` (both reviewers found that the first version accepted any `method`, e.g. `"get"`). Regression test of the selector against the real config: `scripts/form-method-rule.test.mjs`. Runs in `npm run lint`, which is the CI job "Lint, typecheck, build".

## Independent review (exercise 1, two passes)

Two fresh subagents, diff only, no author reasoning, both **approve** with no blockers. Found independently by both: the selector accepted `method="get"` and `method={undefined}` (fixed); `.jsx` not covered (fixed); stories not covered (accepted – not product code). Found by one: forms with a React `action` would be forced to add a `method` React rejects (fixed – exempt); the run log overstated the leak in the five other forms (corrected); a later `no-restricted-syntax` block would silently replace the rule (comment added); suggested a regression test of the selector (added). The two passes overlapped on 3 of 7 points – the lesson's point that several independent runs find more than one.
